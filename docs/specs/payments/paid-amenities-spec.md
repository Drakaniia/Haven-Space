## 2. Operational Loops (`/loop-me` Workflow Lens)

Every recurring user activity in Paid Amenities is modelled as a closed loop with clear **triggers**, **pushed-right checkpoints** (only asking a human when judgment/approval is required), and **decision-ready briefs**:

1. **Loop A — Property Catalog Setup (On-demand trigger)**
   - **Trigger:** Landlord opens `/landlord/payments/amenities` for a property with no paid amenities (or clicks **Add amenity** / **Use presets**).
   - **Automation:** One-click preset picker pre-fills name, category icon, billing model, unit label, and suggested ₱ rate; landlord adjusts and saves.
   - **Checkpoint:** None after Save — immediately visible in the boarder catalog if `is_active = 1`.
2. **Loop B — Subscription / One-Time Enrollment (Event-triggered)**
   - **Trigger (Boarder path):** Boarder selects an active catalog item on `/boarder/payments/amenities`, picks `quantity` (if `max_slots` allows) + optional note, and submits request (`pending_approval`).
   - **Push right:** System validates slot availability, checks tenancy is `confirmed`, snapshots `unit_price_snapshot` & `billing_model_snapshot`, and sends a single notification brief to the landlord (`"<Boarder> requested <Qty>x <Amenity> (₱<Total>/<cycle>)"`).
   - **Checkpoint (Landlord):** Landlord clicks **Approve** (optionally adjusting `due_date`, default `today + 3d`) or **Reject** (with reason) in the Pending Requests queue.
   - **Outcome:** On approval (or direct Landlord assignment), if `unit_price_snapshot > 0`, the initial `payments` row (`charge_type = 'amenity'`) is created immediately; if `monthly`, `tenancy_amenities.status` becomes `'active'` and `next_bill_date` is anchored to the tenancy's next rent due date.
3. **Loop C — Monthly Recurring Renewal (Schedule-triggered)**
   - **Trigger:** Nightly `runBillingJob` (Manila `UTC+8` date `today`).
   - **Automation (Zero human friction):** For every `tenancy_amenities` row where `status = 'active'`, `billing_model_snapshot = 'monthly'`, `unit_price_snapshot > 0`, and `next_bill_date <= addDays(today, DUE_SOON_DAYS)` (or `<= today` if missed), insert an idempotent `payments` row (`generation_key = 'amenity:<tenancy_amenity_id>:<YYYY-MM-DD>'`), advance `next_bill_date` by 1 month (clamped to the tenancy's move-in day-of-month, matching rent clamping), and emit a `bill_added` / `payment_due_soon` bell to the boarder.
   - **Settlement:** Reuses the existing boarder submission -> landlord verification loop on `/boarder/payments` and `/landlord/payments`.
4. **Loop D — Per-Use & Metered Usage Billing (Event-triggered)**
   - **Trigger 1 (Landlord):** Landlord clicks **Log usage** on a `per_use` catalog item, selects tenant(s), enters `quantity` (or `previous_reading` + `current_reading` for `is_metered`), confirms calculated total and `due_date` (default `today + 3d`), and submits. No extra approval needed — charge posts directly (`status = 'posted'`).
   - **Trigger 2 (Boarder request):** Boarder clicks **Request usage** on a `per_use` item (e.g., 2 laundry loads, 1 overnight visitor), enters quantity + note -> `amenity_usage_logs.status = 'pending_approval'` -> Landlord gets brief and clicks **Confirm & Bill** (editable due date) or **Reject**.
5. **Loop E — Cancellation & Move-Out Cleanup (Event-triggered)**
   - **Trigger:** Boarder clicks **Cancel renewal** on an active `monthly` subscription, OR Landlord clicks **Remove / End** on a subscription, OR Tenancy ends (`leave-request` finalized / `leave-now`).
   - **Automation:** Sets `tenancy_amenities.status = 'cancelled'`, `cancelled_at = CURRENT_TIMESTAMP`, releasing occupied slots (`max_slots`) immediately and preventing Loop C from generating future cycles. Already-posted unpaid `payments` rows remain open and still gate leave approval (`approve-leave-request`).

## 4. Data Model (`workers/api/migrations/0025_paid_amenities.sql`)

```sql
-- 1. Property-level paid amenities catalog (distinct from `amenities` listing tags).
CREATE TABLE IF NOT EXISTS paid_amenities (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  property_id INTEGER NOT NULL,
  name TEXT NOT NULL,
  description TEXT,
  icon TEXT NOT NULL DEFAULT 'sparkles',
  billing_model TEXT NOT NULL CHECK (billing_model IN ('monthly', 'per_use', 'one_time')),
  price REAL NOT NULL DEFAULT 0,
  unit_label TEXT NOT NULL DEFAULT 'unit',
  is_metered INTEGER NOT NULL DEFAULT 0,
  is_included INTEGER NOT NULL DEFAULT 0,
  max_slots INTEGER,
  allow_boarder_request INTEGER NOT NULL DEFAULT 1,
  is_active INTEGER NOT NULL DEFAULT 1,
  created_by INTEGER,
  created_at TEXT NOT NULL DEFAULT CURRENT_TIMESTAMP,
  updated_at TEXT NOT NULL DEFAULT CURRENT_TIMESTAMP,
  FOREIGN KEY (property_id) REFERENCES properties(id) ON DELETE CASCADE,
  FOREIGN KEY (created_by) REFERENCES users(id) ON DELETE SET NULL
);

CREATE INDEX IF NOT EXISTS idx_paid_amenities_property
  ON paid_amenities(property_id, is_active);

-- 2. Tenancy subscriptions & one-time/monthly enrollment requests.
CREATE TABLE IF NOT EXISTS tenancy_amenities (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  paid_amenity_id INTEGER NOT NULL,
  application_id INTEGER NOT NULL,
  property_id INTEGER NOT NULL,
  boarder_id INTEGER NOT NULL,
  room_id INTEGER NOT NULL,
  status TEXT NOT NULL CHECK (status IN ('pending_approval', 'active', 'rejected', 'cancelled', 'completed')),
  quantity INTEGER NOT NULL DEFAULT 1,
  unit_price_snapshot REAL NOT NULL,
  billing_model_snapshot TEXT NOT NULL CHECK (billing_model_snapshot IN ('monthly', 'per_use', 'one_time')),
  anchor_day INTEGER,
  next_bill_date TEXT,
  last_billed_date TEXT,
  notes TEXT,
  rejection_reason TEXT,
  requested_by INTEGER,
  approved_by INTEGER,
  approved_at TEXT,
  cancelled_at TEXT,
  created_at TEXT NOT NULL DEFAULT CURRENT_TIMESTAMP,
  updated_at TEXT NOT NULL DEFAULT CURRENT_TIMESTAMP,
  FOREIGN KEY (paid_amenity_id) REFERENCES paid_amenities(id) ON DELETE CASCADE,
  FOREIGN KEY (application_id) REFERENCES applications(id) ON DELETE CASCADE,
  FOREIGN KEY (property_id) REFERENCES properties(id) ON DELETE CASCADE,
  FOREIGN KEY (boarder_id) REFERENCES users(id) ON DELETE CASCADE,
  FOREIGN KEY (room_id) REFERENCES rooms(id) ON DELETE CASCADE
);

CREATE INDEX IF NOT EXISTS idx_tenancy_amenities_app_status
  ON tenancy_amenities(application_id, status);
CREATE INDEX IF NOT EXISTS idx_tenancy_amenities_due
  ON tenancy_amenities(status, billing_model_snapshot, next_bill_date);
CREATE INDEX IF NOT EXISTS idx_tenancy_amenities_catalog
  ON tenancy_amenities(paid_amenity_id, status);

-- 3. Per-use & metered usage logs (both direct landlord logs and boarder requests).
CREATE TABLE IF NOT EXISTS amenity_usage_logs (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  paid_amenity_id INTEGER NOT NULL,
  application_id INTEGER NOT NULL,
  property_id INTEGER NOT NULL,
  boarder_id INTEGER NOT NULL,
  payment_id INTEGER,
  status TEXT NOT NULL CHECK (status IN ('pending_approval', 'posted', 'rejected')),
  quantity REAL NOT NULL,
  unit_price_snapshot REAL NOT NULL,
  previous_reading REAL,
  current_reading REAL,
  total_amount REAL NOT NULL,
  usage_date TEXT NOT NULL,
  notes TEXT,
  rejection_reason TEXT,
  logged_by INTEGER NOT NULL,
  reviewed_by INTEGER,
  reviewed_at TEXT,
  created_at TEXT NOT NULL DEFAULT CURRENT_TIMESTAMP,
  updated_at TEXT NOT NULL DEFAULT CURRENT_TIMESTAMP,
  FOREIGN KEY (paid_amenity_id) REFERENCES paid_amenities(id) ON DELETE CASCADE,
  FOREIGN KEY (application_id) REFERENCES applications(id) ON DELETE CASCADE,
  FOREIGN KEY (property_id) REFERENCES properties(id) ON DELETE CASCADE,
  FOREIGN KEY (boarder_id) REFERENCES users(id) ON DELETE CASCADE,
  FOREIGN KEY (payment_id) REFERENCES payments(id) ON DELETE SET NULL
);

CREATE INDEX IF NOT EXISTS idx_amenity_usage_property_status
  ON amenity_usage_logs(property_id, status, created_at);
CREATE INDEX IF NOT EXISTS idx_amenity_usage_app
  ON amenity_usage_logs(application_id, created_at);

-- 4. Optional traceability links on payments (no breaking schema change).
ALTER TABLE payments ADD COLUMN paid_amenity_id INTEGER;
ALTER TABLE payments ADD COLUMN tenancy_amenity_id INTEGER;
ALTER TABLE payments ADD COLUMN amenity_usage_log_id INTEGER;
```

## 5. Detailed Behaviour & Business Rules

### 5.1 Charge Type & Late-Fee Exemption

1. Add `'amenity'` to `CHARGE_TYPES` in `workers/api/src/repositories/payments/helpers.ts` and `PaymentChargeType` in `apps/web/src/lib/types/payments.ts`.
2. Add `amenity: 'Amenity'` to `CHARGE_TYPE_LABELS` in `apps/web/src/lib/payments.ts`.
3. Update `applyLateFees` in `workers/api/src/repositories/payments/billing-run.ts` to filter:
   `WHERE pay.status = 'overdue' AND pay.charge_type NOT IN ('late_fee', 'amenity')`.
   Overdue `amenity` charges still flip to `overdue` in `markOverdue()` and emit `payment_overdue_landlord` / `payment_due_soon` notifications.

### 5.2 Catalog Validation & Presets

- `billing_model`: `'monthly' | 'per_use' | 'one_time'`.
- `price`: finite number `>= 0` (rounded to 2 decimals via `roundMoney`). If `is_included = 1`, `price` is forced to `0`.
- `max_slots`: `NULL` (unlimited) or positive integer `>= 1`. When lowering `max_slots` below currently occupied units (`SUM(quantity)` where `status IN ('active', 'pending_approval')`? — check: occupied = `SUM(quantity)` where `status = 'active'`), allow saving and block *new* requests/assignments until occupied `< max_slots`.
- `is_metered`: only valid when `billing_model = 'per_use'` (otherwise forced `0`).
- **One-click PH Boarding-House Presets** (frontend preset drawer/chips, editable before save):
  1. `Air conditioning` — `monthly`, ₱1,500, unit `unit`, icon `aircon`
  2. `Aircon sub-meter` — `per_use`, ₱18, unit `kWh`, `is_metered: true`, icon `aircon`
  3. `Mini-fridge / Appliance` — `monthly`, ₱400, unit `unit`, icon `kitchen`
  4. `Rice cooker / Kettle` — `monthly`, ₱150, unit `unit`, icon `kitchen`
  5. `Dedicated Parking Slot` — `monthly`, ₱600, unit `slot`, `max_slots: 4`, icon `parking`
  6. `Laundry Machine` — `per_use`, ₱60, unit `load`, icon `laundry`
  7. `High-Speed WiFi Upgrade` — `monthly`, ₱300, unit `device`, icon `wifi`
  8. `Drinking Water Refill` — `per_use`, ₱35, unit `gallon`, icon `sparkles`
  9. `Storage Locker` — `monthly`, ₱150, unit `locker`, `max_slots: 10`, icon `furnished`
  10. `Overnight Visitor Pass` — `per_use`, ₱150, unit `night`, icon `users`
  11. `Keycard / Gate Fob` — `one_time`, ₱200, unit `card`, icon `shieldCheck`

### 5.3 Capacity & Quantity Rules

- Active slots used for a catalog item = `COALESCE(SUM(quantity), 0)` across `tenancy_amenities` where `paid_amenity_id = ? AND status = 'active'`.
- When a boarder submits a `monthly` or `one_time` request (or landlord assigns/approves one):
  - Check `quantity` is an integer `>= 1` and `<= 20`.
  - If `max_slots !== null` and `active_slots + quantity > max_slots`, reject with `409` (`code: 'amenity_slots_full'`, message: `"Not enough available slots for this amenity"`).
- Multiple subscriptions to the same catalog item for the same tenancy: allowed (either by submitting a new request or incrementing quantity), provided total slots fit `max_slots`.

### 5.4 Subscription Approval, Direct Assignment & Initial Billing

- **Tenancy eligibility:** `application` must belong to the property and have `status = 'confirmed'` (active boarder).
- **Boarder request:** allowed only when `paid_amenities.is_active = 1` and `allow_boarder_request = 1`. Creates `tenancy_amenities` with `status = 'pending_approval'`, snapshots `unit_price_snapshot = paid_amenities.price` and `billing_model_snapshot = paid_amenities.billing_model`, and notifies the landlord (`type: 'amenity_request'`).
- **Landlord Approve (`POST .../requests/:id/approve`) or Direct Assign (`POST .../assign`):**
  - Verifies `max_slots` capacity inside D1 write sequence.
  - Resolves `dueDate` (optional body override `YYYY-MM-DD`, default `addDays(manilaToday(), 3)`).
  - For `monthly`:
    - Sets `status = 'active'`, `anchor_day = dayOfMonth(application.move_in_date ?? manilaToday())`, `last_billed_date = manilaToday()`, and `next_bill_date = nextClampedMonthlyDate(application, manilaToday())` (matching `nextDueDate` clamping from `payments/helpers.ts`: e.g., if rent due day is the 20th and today is the 12th, `next_bill_date` is the 20th of *next* month so the tenant isn't double-billed 8 days later; wait — clarify exact rule: **at least 15 days** or **next cycle after activation**? Concrete rule: `next_bill_date` = first rent due day strictly **after** `addDays(today, 14)`, clamped to month length! That guarantees a tenant who activates on the 18th and pays full month on the 18th doesn't get hit again on the 20th two days later, while aligning cleanly to the rent due day thereafter).
    - If `unit_price_snapshot > 0`: inserts immediate `payments` charge (`charge_type = 'amenity'`, `amount = roundMoney(unit_price_snapshot * quantity)`, `due_date = dueDate`, `description = "<Name> (×<Qty>) — Initial month"`, `generation_key = 'amenity_init:<tenancy_amenity_id>'`).
  - For `one_time`:
    - Sets `status = 'completed'` (one-time items don't recur).
    - If `unit_price_snapshot > 0`: inserts `payments` charge (`charge_type = 'amenity'`, `amount = roundMoney(unit_price_snapshot * quantity)`, `due_date = dueDate`, `description = "<Name> (×<Qty>)"`, `generation_key = 'amenity_once:<tenancy_amenity_id>'`).
  - Emits notification to boarder (`type: 'amenity_approved'` or `'amenity_assigned'`).
- **Landlord Reject (`POST .../requests/:id/reject`):**
  - Requires optional `reason` (trimmed), sets `status = 'rejected'`, notifies boarder (`type: 'amenity_rejected'`).

### 5.5 Nightly Recurring Renewal (`runBillingJob`)

- Add `generateAmenityRenewals(db, today)` inside `runBillingJob(db, now)` in `workers/api/src/repositories/payments/billing-run.ts` (before `markOverdue`).
- Query `tenancy_amenities ta JOIN applications app ON ta.application_id = app.id JOIN paid_amenities pa ON ta.paid_amenity_id = pa.id` where:
  - `ta.status = 'active'`
  - `ta.billing_model_snapshot = 'monthly'`
  - `ta.unit_price_snapshot > 0`
  - `app.status = 'confirmed'`
  - `ta.next_bill_date <= addDays(today, 3)` (issues upcoming monthly amenity charge 3 days before due date so boarders get advance visibility alongside rent).
- For each due subscription:
  - `dueDate = ta.next_bill_date`
  - `amount = roundMoney(ta.unit_price_snapshot * ta.quantity)`
  - `generationKey = "amenity:" + ta.id + ":" + dueDate`
  - `INSERT OR IGNORE INTO payments (..., charge_type, description, amount, due_date, status, generation_key, paid_amenity_id, tenancy_amenity_id) VALUES (..., 'amenity', description, amount, dueDate, 'pending', generationKey, ta.paid_amenity_id, ta.id)`
  - Advance `ta.next_bill_date` by 1 month using `ta.anchor_day` clamped to month-end (`nextMonthlyDue(dueDate, ta.anchor_day)`), and update `ta.last_billed_date = dueDate`.
  - If a row was inserted, emit `bill_added` notification to `boarder_id`.
- Add `amenities_billed: number` to `BillingRunResult` in `billing-run.ts`.

### 5.6 Per-Use & Metered Usage Logging

- **Calculation:**
  - Non-metered (`is_metered = 0`): `quantity > 0`, `total_amount = roundMoney(quantity * unit_price_snapshot)`.
  - Metered (`is_metered = 1`): accepts `previous_reading >= 0` and `current_reading > previous_reading` (`quantity = roundMoney(current_reading - previous_reading)`), OR direct `quantity > 0` if readings omitted; `total_amount = roundMoney(quantity * unit_price_snapshot)`.
- **Landlord direct log (`POST /api/landlord/properties/:propertyId/amenities/:amenityId/usage`):**
  - Supports single boarder or multi-boarder batch (`application_ids: number[]`).
  - Creates `amenity_usage_logs` (`status = 'posted'`) and, if `total_amount > 0`, immediately creates the `payments` row (`charge_type = 'amenity'`, `due_date = body.due_date ?? addDays(today, 3)`, `description = "<Name> · <Qty> <unit_label>" + (readings ? " (<prev>→<curr>)" : "")`), linking `payment_id` and `amenity_usage_log_id`, and sends `bill_added` notification to each boarder.
- **Boarder per-use request (`POST /api/boarder/payments/amenities/:amenityId/usage-request`):**
  - Allowed when `billing_model = 'per_use'`, `is_active = 1`, `allow_boarder_request = 1`.
  - Creates `amenity_usage_logs` (`status = 'pending_approval'`, `payment_id = NULL`) and notifies landlord (`type: 'amenity_usage_request'`).
  - Landlord confirms (`POST /api/landlord/payments/amenities/usage/:logId/approve`, optional `due_date` override) -> creates `payments` row + updates log to `'posted'` + notifies boarder; or rejects (`.../reject`) -> `'rejected'` + notifies boarder.

### 5.7 Rate Update, Cancellation & Tenancy End

- **Update active subscription rate (`PATCH /api/landlord/payments/amenities/subscriptions/:id`):** Landlord may update `unit_price_snapshot` (effective on future cycles) or `quantity` (respecting `max_slots`).
- **Cancel subscription (`POST /api/boarder/payments/amenities/subscriptions/:id/cancel` or `POST /api/landlord/payments/amenities/subscriptions/:id/cancel`):**
  - Boarder may cancel their own `pending_approval` or `active` subscription; landlord may cancel any on their property.
  - Sets `status = 'cancelled'`, `cancelled_at = CURRENT_TIMESTAMP`. Does **not** cancel or refund already-posted `payments` rows.
- **Auto-cancel on tenancy end:** Wherever a tenancy transitions out of `confirmed` (leave finalization in `workers/api/src/repositories/landlord-boarders.ts` / `leave-now` / `tenancy.ts`), execute:
  `UPDATE tenancy_amenities SET status = 'cancelled', cancelled_at = CURRENT_TIMESTAMP, updated_at = CURRENT_TIMESTAMP WHERE application_id = ? AND status IN ('pending_approval', 'active')`
  and reject any `pending_approval` `amenity_usage_logs` for that `application_id`.

## 7. API Surface (`workers/api/src/routes/payments/amenities.ts`)

Registered via `registerAmenityRoutes(paymentsRoutes)` in `workers/api/src/routes/payments/index.ts`. All landlord routes enforce `findLandlordRoomProperty(db, propertyId, user.user_id)` (supports co-landlords via `property_access`); all boarder routes enforce `requireBoarder` + `confirmed` tenancy scoped to `user.user_id`.

### Landlord Endpoints
- `GET /api/landlord/payments/amenities?propertyId=<id>` — returns `{ catalog, subscriptions, pending_requests, usage_logs, summary }`.
- `POST /api/landlord/properties/:propertyId/amenities` — create catalog item (single or batch preset array).
- `PATCH /api/landlord/payments/amenities/:amenityId` — edit catalog item (`name`, `price`, `max_slots`, `unit_label`, `is_metered`, `is_included`, `allow_boarder_request`, `is_active`, `icon`, `description`).
- `POST /api/landlord/properties/:propertyId/amenities/:amenityId/assign` — directly assign `monthly` or `one_time` amenity to `application_id` (`quantity`, optional `due_date`, optional `notes`).
- `POST /api/landlord/payments/amenities/requests/:subscriptionId/approve` — approve pending `tenancy_amenities` request (optional `due_date`).
- `POST /api/landlord/payments/amenities/requests/:subscriptionId/reject` — reject with optional `reason`.
- `PATCH /api/landlord/payments/amenities/subscriptions/:subscriptionId` — update `quantity` or `unit_price_snapshot` for future cycles.
- `POST /api/landlord/payments/amenities/subscriptions/:subscriptionId/cancel` — cancel subscription (stops future renewals).
- `POST /api/landlord/properties/:propertyId/amenities/:amenityId/usage` — log `per_use` / metered usage (`application_ids`, `quantity` or `previous_reading`/`current_reading`, optional `due_date`, `usage_date`, `notes`).
- `POST /api/landlord/payments/amenities/usage/:logId/approve` — approve boarder usage request & post charge (optional `due_date`).
- `POST /api/landlord/payments/amenities/usage/:logId/reject` — reject boarder usage request.

### Boarder Endpoints
- `GET /api/boarder/payments/amenities` — returns active confirmed tenancy's property catalog, boarder's subscriptions, usage logs, and recent amenity charges.
- `POST /api/boarder/payments/amenities/:amenityId/request` — request `monthly` or `one_time` amenity (`quantity`, optional `notes`).
- `POST /api/boarder/payments/amenities/:amenityId/usage-request` — request `per_use` usage (`quantity`, optional `notes`, optional `usage_date`).
- `POST /api/boarder/payments/amenities/subscriptions/:subscriptionId/cancel` — cancel own `pending_approval` or `active` subscription.

## 8. Edge Cases

1. **Double-nested layout trap:** Because `apps/web/src/routes/landlord/payments.tsx` and `apps/web/src/routes/boarder/payments.tsx` already render `Protected` + `RoleShell`, the new leaf routes (`amenities.tsx`) must render only their page content (never `Protected`/`RoleShell`).
2. **Slot race / capacity overflow:** Checking `active_slots + quantity <= max_slots` happens both on boarder request and again on landlord approval/assignment so two pending requests for the last parking slot cannot both be approved.
3. **Price edits vs active subscribers:** Editing `paid_amenities.price` never mutates `tenancy_amenities.unit_price_snapshot`; landlords must explicitly update a subscription if they want an active tenant's rate to change.
4. **Move-in on day 29/30/31:** `next_bill_date` uses the same end-of-month clamping helper as rent (`nextMonthlyDue`), keeping `anchor_day` intact across February and 30-day months.
5. **Archived amenity with active subscribers:** Archiving (`is_active = 0`) hides the item from new boarder requests, while existing active `monthly` subscriptions continue renewing until cancelled.
6. **Zero-price (`is_included`) amenities:** Never insert ₱0 rows into `payments`; still track slots (`max_slots`), approval, and cancellation cleanly.
7. **Unpaid amenity charges on leave:** Because amenity charges live in `payments` (`status IN ('pending', 'overdue', 'awaiting_verification')`), the existing leave-approval balance gate automatically prevents move-out clearance until settled or cancelled.

## 9. Tests & Verification Bar

1. **API tests (`workers/api`):**
   - Catalog CRUD + preset creation + archive (`is_active = 0`) + co-landlord authorization + cross-landlord 404 isolation.
   - Slot capacity enforcement (`max_slots`, `quantity > 1`, two competing requests for 1 remaining slot).

## 10. Acceptance Criteria

- Both Landlord and confirmed Boarder see `Amenities` under the `Payments` sidebar group and land on clean, non-double-nested screens.
- Landlord can create/edit/archive property paid amenities (Monthly, Per-use/Metered, One-time, Included) or add PH boarding-house presets in one click.
- Boarders can request available amenities (respecting `max_slots`) and cancel active renewals; landlords can approve/reject requests, directly assign amenities, and log metered or per-use charges.
- All billable amenity events produce `charge_type = 'amenity'` rows on `payments`, payable and verifiable through the existing Payments flows, included in CSV/statements, and exempt from automatic late fees.
- Monthly amenity renewals run automatically and idempotently in `runBillingJob`, and stop automatically when cancelled or when a tenancy ends.

## 11. Out of Scope

- Online payment gateway / automated e-wallet checkout (payments remain manual proof + verification).
- Mid-month day-by-day pro-rating or automated refunds on early cancellation.
- Time-slot reservation calendar (hourly room/facility booking) — tracked only via quantity/slots and usage logs.
- Admin role visibility or platform-wide amenity analytics.
